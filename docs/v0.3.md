# Earth One v0.3 — Preprocessing Engine Contract

## Purpose

v0.3 establishes the first analysis-ready boundary.

The system must not send raw satellite products directly into an AI model.

The intended boundary is:

**raw observation**
→ **quality assurance**
→ **sensor-aware preprocessing**
→ **standardized analysis-ready product**
→ **AI/model routing**

## Current implementation

This version establishes and tests the deterministic preprocessing contract:

- sensor identity
- source path
- output directory
- target CRS
- target spatial resolution
- cloud-mask requirement
- nodata value
- resampling method
- processor version

It also adds local file QA.

## Why the actual raster transformation is separated

Sentinel-1 and Sentinel-2 are not interchangeable.

### Sentinel-2

The eventual preprocessing chain will need to account for:

- multispectral bands
- surface-reflectance product semantics
- cloud/scene classification information
- band-specific spatial resolution
- nodata/invalid pixels

### Sentinel-1

The eventual chain must account for:

- SAR polarization
- acquisition geometry/orbit metadata
- GRD measurement characteristics
- terrain/geometric effects
- speckle/noise considerations
- radiometric consistency

Earth One must not hide these sensor-specific scientific decisions inside a
generic "preprocess()" function.

## Target standard

The next executable raster backend should produce a common analysis object
containing:

- sensor
- acquisition timestamp
- CRS
- transform
- width/height
- spatial resolution
- bands/polarizations
- nodata
- quality mask
- source item ID
- processing version

## Research requirement

Every preprocessing transformation must remain reproducible.

A future carbon estimate should be traceable through:

`source observation → preprocessing specification → processed data → model version → result`

## Next build

v0.4 should implement the raster backend for real data and produce the first
analysis-ready Sentinel-2 product.

Only after that should we connect the first AI inference module.
