# Earth One v0.8 — Validation and Uncertainty Layer

## Objective

v0.8 changes the question from:

**"Can the model classify pixels?"**

to:

**"Does the model generalize, and how uncertain are its predictions?"**

## Spatial validation

The development classifier in v0.7 used a conventional stratified pixel split.

v0.8 adds spatial block holdout.

Whole spatial blocks are assigned to train or test, reducing leakage caused by
neighboring pixels appearing in both sets.

Reported metrics:

- accuracy
- balanced accuracy
- macro F1
- weighted F1
- macro precision
- macro recall
- confusion matrix

This is still a development validation system. The final scientific study must
define block size from spatial autocorrelation, landscape scale and study design.

## Temporal validation

v0.8 can evaluate a fixed model against independent temporal feature stacks.

This allows Earth One to test whether a classifier trained on one period
continues to work on later observations.

Reported:

- per-period balanced accuracy
- per-period macro F1
- pooled balanced accuracy
- pooled macro F1

## Confidence calibration

Random Forest maximum class probability is not automatically a calibrated
probability.

v0.8 therefore adds isotonic calibration of the maximum confidence against
observed correctness.

The result is still deliberately described as a **calibrated confidence
indicator**, not a physical probability of disturbance.

## Uncertainty

A first operational uncertainty layer is:

`uncertainty = 1 - calibrated confidence`

This is an uncertainty indicator.

It is **not** a measurement error bar, confidence interval, or carbon uncertainty.

Those require separate propagation models.

## Scientific gate

Earth One should not advance a disturbance classification into biomass/carbon
estimation merely because overall accuracy is high.

The final gate should consider:

- spatial validation
- temporal validation
- class-specific performance
- calibration
- independent reference data
- uncertainty
- event-level errors

## Next: v0.9

v0.9 should introduce event objects and reference-data integration:

```text
pixel predictions
      ↓
spatial aggregation
      ↓
event segmentation
      ↓
event attributes
      ↓
reference matching
      ↓
event-level validation
      ↓
validated disturbance events
```

This will give Earth One a scientifically meaningful object to follow through
time and eventually convert into biomass/carbon change.
