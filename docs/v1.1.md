# Earth One v1.1 — Autonomous Sentinel-1 Production Layer

## Goal

Remove manual QGIS extraction from the research-production workflow. Earth One
now treats Sentinel-1 acquisition as a machine-controlled process:

`AOI -> catalog discovery -> scene metadata normalization -> geometry matching -> exact product selection -> on-demand AOI processing -> raster QC -> manifest`

The processor requests only the frozen research AOI, so the system does not
need to download an 800 MB+ full-swath TIFF merely to analyze a 10 km study
area.

## Scene matching

A temporal pair is accepted only when the candidates have matching:

- relative orbit
- orbit direction
- IW acquisition mode
- compatible polarization

Same slice and same platform are additional scoring bonuses. A pair is rejected
when a required geometry attribute is missing.

## Sentinel-1 processing

Earth One requests calibrated Sentinel-1 GRD through the Copernicus Data Space
Sentinel Hub Process API. The default research product is terrain-corrected
Gamma0 using Copernicus DEM 30 m and orthorectification. The selected real
product ID is embedded in the evalscript scene filter so the API cannot silently
substitute an unrelated acquisition within the time window.

## Mandatory QC gate

Every output raster is inspected immediately. It must have:

- readable GeoTIFF structure
- non-zero valid-pixel count
- finite values
- non-constant value range
- non-empty spatial dimensions

All-zero or empty outputs are rejected and deleted. The pipeline therefore
cannot advance from a successful HTTP/processing response to scientific analysis
without passing raster-value validation.

## Scientific provenance

The selected product ID, acquisition time, orbit, polarization, processing
coefficient, AOI, output dimensions, and QC statistics are retained with the
observation manifest.
